# 只分享某个桌面应用的声音

频道页「一起听」可以只分享**一个应用**的声音（其他应用不受影响）。浏览器平台无法直接按原生应用采声（`getDisplayMedia` 只有标签页音频与整屏系统音频两条路，W3C `windowAudio` 提案截至 2026-11 仍未落地，Chromium 152 实测不支持），因此按目标来源分两种做法：

| 目标                                            | 方案                                                                                           | 成本                 |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------- | -------------------- |
| 网页版音乐/视频（网易云、B 站、Spotify Web 等） | 频道页「一起听」→ 分享标签页的声音 → 选该标签页                                                | 零成本               |
| **桌面客户端/游戏**                             | 「一起听 → 分享本机应用的声音」直连（需 [小工具](../helper/app-audio-bridge/) 后台运行，下文） | `pip install` 三个包 |
| 桌面客户端（备选）                              | 整屏+系统声音 + 音量混合器排除法（附录 B）                                                     | 手动操作             |

## 方案 A：频道页直连小工具（推荐，免驱动、本地零重音）

[app-audio-bridge](../helper/app-audio-bridge/) 用 Windows 10 20H1+ 内置的 **WASAPI 进程级音频回路**（免驱动、免管理员）按进程树采集目标应用的声音；频道页**直接拉取音频流**混入对外发送——不经浏览器选择器、不经过任何本地播放：

```
目标应用 ──进程级回路──▶ app-audio-bridge（127.0.0.1:8790，后台运行）
                              │ HTTP 音频流（float32）
频道成员 ◀──混音发送轨◀── 频道页「一起听 → 分享本机应用的声音」
```

因为音频只进对外混音、不进本地扬声器，**本地从头到尾只有目标应用自己的一重声音**（重音问题从架构上消除）；远端听到的也只有该应用。

### 步骤

1. 启动小工具（一次性安装依赖；之后每次使用前在后台跑着即可，页面可以不开）：

    ```bash
    cd helper/app-audio-bridge
    python -m pip install -r requirements.txt   # proc-tap + psutil + pycaw
    python server.py                            # 自动打开 http://127.0.0.1:8790
    ```

2. 让目标应用（音乐客户端 / 游戏）出声。
3. 频道页 → 点「一起听」→ **分享本机应用的声音** → 列表（只显示能发声的应用，播放中的排最前）选中目标应用。提示「正在分享应用声音」即成功；成员卡出现音符标记。
4. 停止：再点一次「一起听」按钮（小工具的采集会一并停止）。

小工具自带的页面（127.0.0.1:8790）现在只用于**试听确认**：选中应用后本页播放它的声音（与源应用本地重音属正常现象），也可作为频道页直连不可用时的备用路径（把本页当标签页分享，Chrome 会在共享期间自动静音本页的本地播放）。

### 排障

- **菜单里提示未检测到小工具**：确认 `python server.py` 在跑；频道页会探测 127.0.0.1:8790~8769（小工具端口顺延范围内）。
- **应用列表为空**：先让目标应用出声（列表按活跃音频会话实时枚举），重新展开即可。
- **选中后没声**：同名多进程时列表取「播放中」的会话进程；个别受保护进程（带反作弊的游戏）拒绝进程回路采集，改用附录 B。
- **跨源/https 部署**：小工具已带 CORS 与 Private Network 响应头，频道页无论 http 还是 https 都能访问 127.0.0.1。

## 附录 B：零工具的替代做法（备选）

不愿跑小工具时，可退回「整屏 + 系统声音」再用 Windows 自带能力把**其他应用**排除：

- **音量混合器静音法**：频道页「一起听」→ 分享标签页的声音 → 选择器改选「整个屏幕」+ 勾选「同时分享系统声音」；再右键任务栏喇叭 → 音量混合器，把不想分享的应用逐个静音。缺点：每场要手动设置，新冒出的提示音会漏出去。
- **第二设备路由法**：Windows 设置 → 系统 → 声音 → 应用音量和设备首选项，把**其他应用**的输出指到第二设备（蓝牙耳机/USB 声卡），目标应用留在默认扬声器——整屏采集抓的是默认设备回路，其他应用的声音就不在其中。

> VB-CABLE 虚拟声卡方案在评估后未保留入口——需要装驱动并重启，且与第二设备路由法原理相同。若 W3C `windowAudio` 提案落地，选择器里直接选目标窗口即可，所有变通方案都将退役。

## 展望

W3C 正在评审 `getDisplayMedia` 的 `windowAudio` 提案（按窗口/应用直接采声）。Chromium 稳定版落地后，「一起听」在选择器里选目标窗口即可单独采声，小工具与虚拟声卡都将不再必要。
